# 本机独立部署与账号验收

0.1.7 起前后端分别发布，用户入口仍为 **http://127.0.0.1:8100**。Nginx 提供 WebUI 静态资源，并原样转发 `/api/` 与 `/healthz` 至 `127.0.0.1:8101`。Framework 不依赖 Nginx 或前端构建工具。

## 目录与服务

- 后端发布：`~/.local/share/courseflow-local/releases/`；`current` 指向当前版本。
- 前端发布：`~/.local/share/courseflow-local/webui-releases/`；`webui-current` 指向当前版本。
- 数据与主密钥：`~/.local/share/courseflow-local/data/`，前后端拆分不改变数据库版本 3。
- 后端服务：`courseflow-local.service`，设置 `CF_BIND=127.0.0.1:8101`、`CF_PUBLIC_URL=http://127.0.0.1:8100`，保留原 `CF_DATA_DIR`。
- 网关服务：`courseflow-webui-local.service`，使用 WebUI 仓库的 `deploy/nginx.conf`。独立前缀目录下的 `html` 链接指向 `webui-current/dist`，不修改系统 Nginx 配置。
- 日志仍写入私有数据目录，可从界面「日志导出」下载；首次设置码只在后端终端或用户服务日志中显示。

```sh
systemctl --user status courseflow-local courseflow-webui-local
journalctl --user -u courseflow-local -u courseflow-webui-local -n 50 --no-pager
```

## 构建、更新与回退

1. 后端执行 `npm ci`、`npm run typecheck`、`npm test`。智慧树与超星契约测试只启用 fixture；Python 环境通过 `CF_CX_PYTHON` 指定。平台模块本轮不升级。
2. WebUI 执行 `npm ci`、`npm run check`、`npm test`、`npm run build`。分别记录前后端提交编号及文件摘要。
3. 将已提交后端代码导出至新的版本目录，执行 `npm ci --omit=dev`；将前端构建产物放入独立版本目录。不要把数据目录或开发服务器放入发布包。
4. 用临时数据和模拟模块验收同源代理，包括 Cookie、CSRF、带 `%2F` 的课程标识、题图及导出；执行 `nginx -t -p <独立前缀>/ -c <配置绝对路径>`。API 代理不添加 URI 后缀，长请求超时配置为 300 秒。
5. 停止网关及后端，备份数据库、主密钥、模块目录、服务配置、版本链接和发布记录。切换前后端版本链接，启动后端并确认 `web_api_version: 1`，再启动网关。
6. 检查入口、构建资源、`/version.json`、`/healthz`、`/api/bootstrap`、匿名权限边界和既有数据摘要。部署检查不登录真实平台、不执行真实账号任务。

0.1.7 的拆分不迁移数据库，不更换账号、站点会话、模块配置或主密钥。不能并发启动两个使用同一数据目录的后端。网关与后端必须配套设置公开 URL；保持原请求的 Origin 和 Cookie，不添加跨域放行规则。

失败时停止新服务，恢复旧版本链接和服务配置；如果回退到 0.1.6 一体服务，由旧后端重新占用 8100，停用新增网关。仅在数据库确有变更且已核对新增数据时恢复数据库备份，主密钥必须与数据库配套。部署程序和数据备份均保存在源码目录外。

用户级服务随用户会话启动；不修改系统级 linger 设置。历史版本 0.1.4 曾将数据库从版本 2 升级至 3，不能用更旧程序直接读取版本 3。

## 0.1.6 更新

框架 0.1.6 与智慧树 0.3.3 增加按用户保存的超额问答开关和独立成绩分区。超额模式默认关闭，升级不会替用户开启。题库收进框架内置模块，数据库仍为版本 3，保留旧答案记录与主密钥。上线检查不自动发布真实问答或执行真实账号任务。

## 首次登录

框架 0.1.5 可同时安装智慧树与超星独立模块；超星的外部 Python 环境、清单和配置见 [模块 README](https://github.com/Course-Flow-Lab/courseflow-chaoxing)。本次超星验证只使用合成数据，不进行真实账号测试。升级框架继续使用数据库版本 3，不替换现有数据库或主密钥。

导入旧站点数据 请使用 [专用迁移工具](LEGACY-MIGRATION.md)，目标须为全新目录，不向正在运行的数据目录合并。工具不会执行历史任务或激活旧登录态。

在网页输入管理员设置码，创建自己的站点用户名和密码。之后到「平台连接」扫码智慧树。实际部署没有预置平台账号或付费模型密钥。

框架 0.1.4 增加成员注册。管理员进入「注册与邀请」，生成并复制邀请码，交给新成员从登录页「注册账号」使用。手机端入口位于「我的账号」。默认必须使用邀请码；关闭「新用户注册必须提供邀请码」并保存后即可直接注册。每个码仅可使用一次，未使用的码可撤销，完整码只在生成后显示。升级不会改变现有管理员、成员、站点会话或个人设置。

模型服务在「模型与任务设置」中填写；连接检查会向你选择的服务发送简短请求。未配置模型也可在作业任务暂停后人工补答。

该页的「启用夜间暂停（北京时间 23:00–07:00）」默认勾选。取消后保存，当前用户可以全天创建和运行任务；夜间策略暂停的任务会自动继续，人工暂停的任务仍需手动继续。其他用户的开关独立保存。

框架 0.1.2 与智慧树 0.3.1 修正了父域 Cookie 传入官方播放器时的作用范围，并等待短暂的登录跳转。升级后先刷新网页，再创建新的见面课任务；之前已结束且记录为人工处理的任务不会被改写。只有持续登录跳转或平台明确拒绝认证时才重新扫码。完整签到仍以平台回读和官方页面为准。

框架 0.1.3 与智慧树 0.3.2 进一步修正了播放后一次性加载标志复位造成的等待，并区分初始化超时与真正的播放停滞。更新后创建新的见面课任务验证；若仍暂停，在任务详情点击「导出日志」，核对等待阶段、观看历史和媒体状态。不要把旧版本已经结束的跳过记录当成新版本的测试结果。

「日志导出」支持运行日志、操作记录及我的任务日志，按北京时间选择起止日期，最长九十二天。运行日志和操作记录从升级后开始保存，仅管理员可下载；升级前的执行事件仍可通过任务日志导出。日志文件包含诊断信息，源码仓库不收录运行日志或数据库。

## 逐项验收

先选一门课程、一个未完成视频，做 30–180 秒短时试跑，核对官方页面进度后再扩大任务范围。

| 项目 | 需要与官方页面核对 |
| --- | --- |
| 登录 | 扫码、课程列表、共享课与智慧课程目录；重新扫码后旧任务暂停 |
| 学习 | 原速保存、暂停后不累计停留时长、先修或限额提示、完成状态回读 |
| 复习 | 已完成视频、日期轮换、分钟预算、原状态保留、学习习惯分是否更新 |
| 视频互动 | 官方标注答案、模型或手工补答；额外验证时暂停 |
| 作业考试 | 已有答案保留、人工覆盖开关、草稿保存；明确确认后才交卷 |
| 交卷恢复 | 响应未知时只回读原作答，原任务导出区分已确认和未确认 |
| 掌握度 | 免考与满分跳过，最多三轮，未达满分仍显示未达标 |
| 见面课 | 官方播放器登录跳转、历史加载、原速续播、签到回读；无回放、线下和卡住项有记录 |
| 问答 | 互动分和进度格、数量调节、草稿编辑与选中发布、互答开关、可展开记录、回答限额、避免重复发送 |
| 成绩与导出 | 平台计分规则、实际得分、中文报告、题图和公开解析 |
| 调度 | 同账号排队、显式跨课程并行、人工暂停、按用户关闭夜间暂停、晨间恢复 |

不要用正式考试测试网络故障或重试。共享课已提交考试暂不通过重新开考读取，使用原任务报告。验证码、人脸、未开放活动需在官方页面处理。

部署验收仅表示服务运行、接口与页面可用。首次真实账号登录、学习写入、正式交卷、完整见面课签到和真实模型调用均由用户在新站点测试，不能由离线结果替代。
